# 反馈与诊断隐私

请在提供安装包的原帖或原讨论中反馈，无需另行注册、付款或提供账号密码。插件不会自动上传诊断，也没有外部诊断服务器。

## GitHub 问题反馈表单

打开 [v1 问题反馈表单](https://github.com/bingdilian/zz-picker-public/issues/new?template=v1-bug-report.yml)，按提示填写实际手机环境、安装方式、问题阶段、复现步骤和结果，再按需附上已预览检查的诊断或截图。模板对应第一版；GitHub Issues 为整个仓库共用，不会按代码分支分别创建。

也可从仓库的 Issues → New issue 选择“v1 问题反馈”。无法使用表单时，可在原讨论中按下列格式反馈。

## 建议提供的信息

- “说明 / 环境”中的设备型号代码、iOS、转转版本、插件版本与编译变体，以及注入工具名称和版本。
- 从哪个页面启动、希望发生什么、实际停在哪里，以及可重复的操作步骤。
- 自动收藏是否开启，处理上限与时间上限，任务显示的加载、处理、待确认、命中数量和暂停原因。
- 问题出现于安装加载、搜索筛选、报告读取、翻页、收藏、回读、暂停恢复还是分享。

可复制以下文字填写。分享环境面板时请检查截图中是否混入账号或通知：

```text
设备型号代码 / iOS：
转转版本 / 插件版本 / 编译变体：
注入工具及版本：
起始页面与复现步骤：
预期结果 / 实际结果：
自动收藏开关 / 件数上限 / 分钟上限：
任务计数与暂停提示：
是否能重复出现：
附件是否为默认诊断或自选详细诊断：
```

## 导出前先预览

从设置的诊断导出入口生成本地内容，先预览，再由你主动打开系统分享、选择保存或发送对象。生成或预览诊断不会自动向维护者发送，也不会自动发帖。

默认诊断不包含商品明细。主动选择详细诊断后，内容可包含商品标题、商品 ID 与筛选条件，可能暴露你的选机兴趣；只在需要排查时选择，并检查接收对象。硬件信息使用型号代码，不是 UDID 或设备名称。

两种诊断均不应包含原始鉴权信息、完整请求头或原始网络报文。不要附带 Cookie、Token、密码、验证码、账号截图或完整抓包。若你自行添加截图、录屏或其他文件，请先遮挡账号、订单、联系方式、地址和他人信息；这些手工附件不受插件诊断字段过滤保护。

## 发现收藏异常

先全局停用或结束任务，记录提示并手动核对转转收藏页，不要反复点击重试。停止和卸载无法撤回已经发出的收藏。若回读长期无结果，完全关闭并重开转转后再核对，反馈时说明“动作已发出”和“已确认成功”的区别。

未拿到回读或只有本地检查通过，不应报告为“收藏成功”。同样，请把“安装成功”“加载成功”“搜索筛选成功”和“完整任务通过”分开描述，便于判断实际兼容范围。

收藏异常请保留当前任务并导出诊断。`favoriteTrace` 记录尝试、点击结果、实际请求启动、响应码、状态回读及收尾；基础模式隐藏 ID，开启商品明细后才含对应 ID。详细模式还可查看「零件缺失」的报告原文、平台标记与判定，以及收藏失败时记录的数字返回码。诊断省略请求头和原始报文。
